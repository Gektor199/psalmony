# Перенос в Екатеринбург · 0.4.3

Сервер: `91.226.80.181`, hostname `vm-19188deb`. Приложение: https://psalmony.91.226.80.181.sslip.io. Рабочий каталог — `/opt/psalmony`, профиль — `deploy/ekaterinburg/compose.yaml`.

## Состав установки

- Docker Compose: приложение, PostgreSQL 17, собственный UDP relay, Caddy с сертификатом Let's Encrypt.
- TCP 80/443; собственный звук UDP 22126; порт Jamulus UDP 22124 закрыт. PostgreSQL не опубликован наружу.
- База и вложения — отдельные volumes. Секреты перенесены по SSH в `.env`, права 600; в Git отсутствуют.
- Клиенты 0.4.3 используют новый API и аудиоадрес. Старые установщики направлены в Москву и требуют обновления.

## Проверки

- При остановленной записи сняты дамп PostgreSQL, архив вложений и архив старой установки. SHA256 архивов проверены после передачи.
- До запуска нового приложения все 9 таблиц совпали с оригиналом по количеству строк и MD5 упорядоченного JSON-содержимого. Перенесены 10 пользователей, 10 групп, 10 записей членства, одно вложение и прочие служебные данные.
- У существующей комнаты с московским адресом изменён endpoint и город, revision увеличен. Исторические отчёты об измерениях не переписаны.
- Контрольные суммы таблиц до и после перезапуска PostgreSQL и приложения совпали. SHA256 файла вложения совпал с резервной копией.
- HTTPS `/api/health` возвращает `ok: true`, `version: 0.4.3`, `database: postgresql`.
- 29 локальных тестов прошли, 2 интеграционных сценария в общем запуске пропущены. Отдельный запуск API-интеграции через публичный HTTPS прошёл 19 проверок, включая авторизацию, изоляцию, роли, конкурирующие записи и вложения; временные записи удалены.
- Зашифрованный UDP JOIN и собственный возврат тестового PCM через новый сервер прошли, в том числе после перезапуска. Это синтетический сигнал, не запись микрофона.
- Jamulus ответил из внутренней сети и на внешнюю пробу с Mac. Первые внешние пробы терялись: качество сети и совместная игра ещё требуют отдельной проверки.
- Mac universal DMG и Windows x64 installer 0.4.3 собраны, публичные HTTPS-загрузки совпали с локальными SHA256.
- Установленный Mac-клиент обновлён, отображает v0.4.3 и прежнюю библиотеку из 7 песен. Локальный gateway достигает нового API; проверки Host/Origin/token прошли. Физический Windows и восемь музыкантов не проверены. Mac без нотариализации, Windows без Authenticode.

## Старая установка и восстановление

В Москве удалены три контейнера основного Psalmony, контейнер Jamulus, их отдельные сети, три именованных образа и каталоги `/opt/psalmony`, `/opt/psalmony-rehearsal`. Остальные сервисы (включая NetBird и Volna) остались работающими.

Для восстановления сохранены исходные volumes `psalmony_psalmony-postgres` и `psalmony_psalmony-data`, архивы в `/root/psalmony-migration-20261011` на старом сервере, в `/root/ekb-migration-20261011` на новом и в игнорируемом `backups/ekb-migration-20261011` на Mac. Это разовая копия перед миграцией; новые изменения она не содержит.

Не запускайте старый сервер параллельно с новым для записи: возникнут две расходящиеся базы. Для возврата после новых изменений сначала остановите запись и снимите свежие согласованные дамп и вложения с Екатеринбурга. Не удаляйте volumes при обычном перезапуске.

Браузерный домен изменился: потребуется войти снова, офлайн-кэш старого домена автоматически не переносится. У desktop-клиента локальный origin сохранён.

После проверки переноса по просьбе пользователя Jamulus удалён также из Екатеринбурга: контейнер и образ удалены, service и переменные JAMULUS убраны из рабочего Compose, ссылка на старый пилот убрана из интерфейса. Адрес старой комнаты очищен с увеличением revision; исторический отчёт сохранён.
