# Psalmony 0.6.0 — проверка релиза

Дата: 11 октября 2026 года. Результаты относятся к текущему рабочему дереву 0.6.0, а не к опубликованному production-релизу.

## Среда и фактический результат

- Сервер: `http://127.0.0.1:3190`, запущенный из актуального `server/index.mjs` процесс Node 25.6.0, перезапущенный после исправлений аудита. PostgreSQL: отдельная локальная база `psalmony_release_060`, порт 54329.
- Окончательный полный Node suite: **108 tests, 107 pass, 0 fail, 1 skip**. Пропущен только opt-in тест ответа настоящего Jamulus по UDP: `TEST_JAMULUS=1` не задавалась. Юнит-тесты протокола и проверки ошибки DNS исполнялись. Локальный лог последнего запуска: `/tmp/psalmony-qa060-final.log`.
- Все интеграционные наборы были включены: `TEST_BASE`, `IDENTITY_TEST_BASE`, `ACCOUNT_LIFECYCLE_TEST_BASE`, `RELEASE_TEST_BASE` указывали на 3190; `DATABASE_URL` — только на `psalmony_release_060`.
- `npm run check`, отдельные `node --check` для `public/drafts.js`, `public/account-controls.js`, `server/account-lifecycle.mjs`, нового release-теста и `git diff --check`: **pass**.
- В QA используется явно заданный тестовый секрет аудиобилетов. Приватные рабочие ключи не читались и не переносились в тесты.
- Перед полным suite очищена только таблица `auth_limits` отдельной тестовой базы, чтобы предыдущие тестовые попытки не исказили результаты. Данные рабочей БД и volumes не удалялись. Новые release-тесты удаляют только созданные ими строки и свой временный файл.

Команда воспроизведения, после запуска изолированного сервера с соответствующим тестовым аудиосекретом:

```sh
TEST_BASE=http://127.0.0.1:3190 \
IDENTITY_TEST_BASE=http://127.0.0.1:3190 \
ACCOUNT_LIFECYCLE_TEST_BASE=http://127.0.0.1:3190 \
RELEASE_TEST_BASE=http://127.0.0.1:3190 \
DATABASE_URL=postgres://psalmony:psalmony-local@127.0.0.1:54329/psalmony_release_060 \
RELEASE_AUDIO_TICKET_SECRET=aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa \
node --test tests/*.test.mjs
```

Эти реквизиты предназначены только для изолированной локальной проверки. Lifecycle и release-тесты отказываются от endpoint вне loopback и базы без тестового имени. Повторный запуск в пределах окна rate limit может потребовать ожидания либо согласованного сброса `auth_limits` именно в тестовой БД.

Проверены гонки удаления с созданием, входом, приглашением и передачей владения, а также одновременный выход разных участников из двух групп без deadlock. |
| Аудиодоступ | Билет содержит hash текущей сессии, user и band. Отозванная сессия больше не получает билет; вышедший участник не получает билет прежней группы. Relay unit-тесты проверяют доступ до admission, отказ при ошибке проверки, повторное использование отозванного билета и лимит участников. |

Проверены HTTP 400/403/409/500, queue/context race, scoped copy и восстановление при изменившейся revision или роли viewer. Второе сохранение в очереди после 401 отклоняется, сохраняя черновик; поздние poll/refresh/bootstrap/save-ответы не восстанавливают вышедший аккаунт и не завершают новую сессию. |

## Закрытые замечания аудита

1. **Смена аккаунта в другой вкладке при общей группе.** `PUT /api/state` передаёт ожидаемые `userId` и `bandId`; сервер отклоняет чужой контекст. Regression проверяет одинаковую группу с двумя действующими редакторами и отсутствие записи. Запрос logout из старого контекста также не удаляет новую сессию.
2. **Загрузка в группу, выбранную другой вкладкой.** Uploads передают `X-User-Id` и `X-Band-Id`. Ошибочная личность или группа отклоняются до записи. Gateway передаёт эти заголовки серверу; HTTP-регрессии файла, аватара и обложки проходят.
3. **Ссылка справки.** Добавлена самостоятельная `/help`; HTTP-проверка возвращает 200 и HTML справки.
4. **Ложный успех второго сохранения после 401.** Очередь проверяет захваченный контекст. Regression на реальном orchestration-коде `app.js` подтверждает отказ второй записи и сохранённый scoped-черновик, без `{status:'server'}`.

В пределах перечисленных программных сценариев незакрытых блокирующих дефектов после окончательного запуска не осталось. Это не заменяет проверки ниже.

## Ограничения этой проверки

- Browser UI-сценарии выполняет основной агент отдельно. Этот отчёт не засчитывает чтение кода и VM-тесты за физическую проверку Safari/iOS, Chrome/Android, клавиатуры или layout 390/768/1440.
- Чтение сохранённого state из PostgreSQL подтверждено; перезапуск контейнера приложения с сохранением контрольного fixture в этой QA-сессии не выполнялся. Node3190 не является доказательством Docker build или release deploy.
- Не выполнены проверка физических аудиоустройств, настоящая групповая репетиция, задержка, Bluetooth, MIDI, микрофон, установка PWA, подпись/нотариализация и запуск macOS/Windows-артефактов.
- Публичные legal-страницы помечены как проекты. Отсутствующие подтверждённые реквизиты оператора/контакт, юридическое утверждение и восстановление по email не считаются закрытыми тестами.
- Production, remote push, публикация сайта и installer URLs на production этой QA-сессией не менялись и не подтверждались.
