# Psalmony

Музыкальное пространство для репертуара, подготовки выступлений и работы группы. Адаптивная PWA для браузеров на iOS, Android, macOS, Windows и Linux. Дизайн вдохновлён [Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/design-principles). Серверная база данных — **только PostgreSQL**.

## Установка

Подробная инструкция: **[docs/INSTALL.md](docs/INSTALL.md)** — Docker, разработка, собственный аудиосервер, сборка Mac/Windows и развёртывание на другом хосте.

## Запуск

```sh
git clone https://github.com/Gektor199/psalmony.git
cd psalmony
```

```sh
docker compose up -d --build
```

Открыть <http://127.0.0.1:3180>. PostgreSQL 17 и Node.js 24 запускаются в Docker. Приложение и БД привязаны к loopback; посторонние устройства не получают доступ автоматически. Все данные сохраняются в именованных Docker volumes:

- `psalmony-postgres` — PostgreSQL;
- `psalmony-data` — загруженные вложения.

Остановка без удаления данных: `docker compose stop`. Повторный запуск: `docker compose up -d`. Не удаляйте volumes, если хотите сохранить библиотеку.

Открыв приложение, пользователь получает отдельное гостевое пространство с учебными песнями. Создание аккаунта сохраняет это пространство; вход с другого устройства открывает ту же библиотеку. Приглашения одноразовые и действуют 7 дней.

## Реализовано

- Библиотека: создание и редактирование песен, поиск по названию/исполнителю/тексту, теги, избранное, сортировки, копирование и удаление.
- ChordPro: импорт и экспорт, текстовые разделы, транспонирование включая slash-аккорды, каподастр, Nashville numbers, печать через браузер/PDF.
- Аранжировки: редактируемые блоки, повторы одного блока, перетаскивание и стрелки для порядка исполнения. Существующий ChordPro преобразуется при открытии конструктора; изменения применяются после сохранения.
- Сет-листы: песни с повторениями, изменение порядка, паузы, заметки, общая длительность, дата, место, роли музыкантов, копирование и экспорт ICS.
- Календарь репетиций и выступлений.
- Группы: несколько пространств в одном аккаунте, владелец/редактор/наблюдатель, приглашения, отзыв доступа.
- PostgreSQL: пользователи, хешированные сессии, группы, членство, приглашения, метаданные файлов; версия библиотеки и документы песен/сетов в JSONB.
- Синхронизация: автоматическая отправка изменений, обновления участников каждые 8 секунд, оптимистическая блокировка с явным разрешением конфликтов. Конфликт никогда не перезаписывает другую версию автоматически.
- Офлайн: кеш оболочки PWA, локальная копия библиотеки, очередь изменений; вложения сохраняются в IndexedDB отдельно или вместе с целым выступлением. Офлайн-аудио открывается в репетиционном плеере, PDF и MusicXML — соответствующими кнопками просмотра.
- Сцена: контрастный экран, размер текста, сохранение личной тональности/каподастра, автопрокрутка, переход между элементами сета, таймер паузы, клавиатура и поддерживаемые MIDI-входы, Wake Lock при наличии API.
- Метроном: Web Audio, акценты, изменяемый размер, Tap Tempo. Тюнер: микрофон и определение частоты.
- Аудио: загрузка, обычный плеер, изменение темпа, независимое транспонирование в репетиционном плеере SoundTouchJS.
- Ноты: просмотр PDF и MusicXML (OpenSheetMusicDisplay). Рукописные заметки сохраняются отдельным рисунком к песне.
- Светлая и тёмная темы; адаптация от телефона до широкого экрана.

## Новое в 0.2

В карточке песни откройте «Конструктор аранжировки». Изменение блока обновляет все его повторения.

В сет-листе нажмите «Скачать выступление» и дождитесь статуса «Готово офлайн». Сохраняются тексты, аранжировки и вложения. Есть прогресс, отмена, продолжение и проверка полноты файлов. Кнопка «Открыть скачанную версию» использует сохранённую копию программы. Внешние ссылки не скачиваются. Браузер может очищать локальные данные, поэтому проверяйте готовность перед концертом. Серверные данные остаются в PostgreSQL; IndexedDB используется только как кеш устройства.

Ведущий нажимает «Вести группу», участники той же группы — «Эфир группы» → «Следовать за ведущим». Передаются номер песни и раздел. Личная тональность, капо и масштаб сохраняются. Можно временно перейти к самостоятельному просмотру. Эфир использует фиксированную копию программы: изменения библиотеки не меняют выступление на ходу.

Участники опрашивают сервер каждые 700 мс; фоновая вкладка/ОС может задерживать обновления. Ведущий подтверждает присутствие каждые 5 секунд; через 20 секунд без подтверждения эфир считается завершённым. При потере связи открытый текст остаётся доступен. Одновременно в группе может работать один ведущий; управление привязано к запустившей эфир вкладке. Эфир программы не синхронизирует аудио; собственная аудиосвязь desktop-клиентов описана ниже в разделе 0.4.

## Архив: пилот Jamulus — 0.3

Этот раздел описывает прежний пилот. В 0.4.3 Jamulus удалён с рабочих серверов и из интерфейса подключения. Для актуальной установки используйте `docs/INSTALL.md` и собственный клиент Psalmony; команды ниже оставлены как историческая справка.

Первый этап: до восьми музыкантов в Екатеринбурге. Оренбург добавляется после отдельной проверки маршрута. Psalmony показывает программу и собирает результаты проверки, установленный клиент Jamulus передаёт звук. Это ещё не встроенная браузерная аудиосвязь.

```sh
docker compose -f compose.yaml -f compose.rehearsal.yaml up -d --build
node scripts/check-jamulus.mjs
TEST_BASE=http://127.0.0.1:3180 TEST_JAMULUS=1 npm test
```

В сет-листе откройте «Репетировать онлайн». Владелец сохраняет адрес сервера группы. Для локального теста — `127.0.0.1:22124`; в Jamulus на этом же компьютере вставьте его в поле адреса подключения. Участники вручную сохраняют город, оборудование, Ping, Overall Delay и впечатление от совместной игры. Неизвестные задержки остаются пустыми. При смене аудиосервера старые результаты помечаются устаревшими. Настройки и отчёты хранятся в PostgreSQL, проверяются права и версии параллельных изменений.

Клиент: [официальная установка Jamulus](https://jamulus.app/wiki/Getting-Started). Для первого теста используйте проводные наушники, Ethernet и аудиоинтерфейс с подходящим драйвером. Выберите вход/выход в Jamulus, подключитесь вдвоём и проверьте уровни на умеренной громкости. Слушайте возвращаемый Jamulus микс; не добавляйте второй программный монитор того же сигнала. Для акустических инструментов и голоса собственный звук полностью исключить нельзя. В первом тесте не используйте видео, Bluetooth и отдельные локальные метрономы; метроном Psalmony между устройствами не синхронизирован.

### Что развёрнуто локально

- Неизменённый Jamulus 3.12.5 собирается из официального тега, архив проверяется SHA-256. Лицензия этого релиза — AGPL-3.0-or-later; точный текст находится в `deploy/jamulus/COPYING`. Исходный архив и лицензия также включены в образ, в `/usr/share/doc/jamulus/`.
- Сервер допускает восемь соединений, не регистрируется в публичном каталоге, запись выключена, JSON-RPC не собран. Звуковые файлы не создаются.
- UDP 22124 опубликован только на loopback. Healthcheck получает настоящий ответ Jamulus по UDP. Индикатор в браузере измеряет доступность от backend до аудиосервера, а не задержку музыканта. Число подключений относится ко всему этому аудиосерверу, не к аккаунтам выбранной группы.
- Привязка адреса в Psalmony не ограничивает доступ к звуку Jamulus. Один экземпляр предназначен для одной одновременно репетирующей группы; разные группы должны иметь разные изолированные аудиосерверы.
- Для другого адреса интерфейс не выполняет произвольный сетевой запрос и не выдаёт автоматическую оценку доступности. Организатор проверяет его в Jamulus.

### Проверка из разных домов

Адрес `127.0.0.1` нельзя отправлять другим участникам: у каждого он означает собственный компьютер. Нужен согласованный сервер в Екатеринбурге или доступный участникам VPN-адрес хоста. Для пробы можно использовать имеющийся московский сервер и измерить задержку из Екатеринбурга. Для закрытого пилота предпочтителен приватный доступ с контролем участников; отсутствие сервера в каталоге Jamulus не является авторизацией.

После выбора хоста задаются `JAMULUS_BIND_IP` (конкретный доступный интерфейс) и `JAMULUS_CLIENT_ADDRESS` (адрес, который вводят музыканты); затем владелец сохраняет этот адрес в комнате. Правила доступа к UDP 22124, HTTPS для Psalmony и маршруты VPN проверяются отдельно. Не публикуйте PostgreSQL. Docker Desktop на Mac подходит для локальной проверки, но не доказывает задержку Linux-сервера и домашних подключений.

План натурного теста: два участника → четыре → восемь; каждый этап не менее 15 минут. Записывайте оборудование, Ping и Overall Delay из Jamulus, слышимые обрывы и оценку удобства. Повторите вечером, когда домашняя сеть занята. Для Оренбурга повторите тот же тест; решение о пригодности принимайте по всей группе. UDP-проверка и настройка восьми слотов не доказывают совместную игру восьми физических устройств.

Остановка только аудиосервера без удаления библиотек:

```sh
docker compose -f compose.yaml -f compose.rehearsal.yaml stop jamulus
```

### Отдельный Linux-сервер для аудио

Скопируйте каталог `deploy/jamulus` на аудиохост. В его `.env` задайте `JAMULUS_BIND_IP` — конкретный интерфейс, доступный музыкантам. Из этого каталога выполните `docker compose up -d --build`. Проект `psalmony-rehearsal` работает отдельно: 8 слотов, запись выключена, порт UDP 22124, лимит памяти 256 МБ. Сборка использует одно ядро с низким приоритетом; runtime не имеет жёсткого лимита CPU, чтобы не добавлять обрывы при смешивании. Доступ к известному адресу не требует аккаунта Psalmony: для закрытой группы используйте VPN или сетевой список разрешённых участников.

Для Psalmony на текущем компьютере задайте в `.env`:

```dotenv
JAMULUS_REMOTE_HOST=audio.example.com
JAMULUS_REMOTE_PORT=22124
JAMULUS_REMOTE_LOCATION=Москва
```

Запустите `docker compose -f compose.yaml -f compose.rehearsal.remote.yaml up -d psalmony`. В комнате репетиции сохраните новый адрес `audio.example.com:22124` и город. Этот режим проверяет фиксированный удалённый хост из конфигурации оператора; произвольные адреса участников не опрашиваются. PostgreSQL и вложения остаются в существующих отдельных volumes. Публичный HTTPS для интерфейса Psalmony — отдельное развёртывание.

Проверка с компьютера участника: `JAMULUS_HOST=audio.example.com node scripts/check-jamulus.mjs`. Это только короткий UDP-ответ; значение `backendRttMs` не является Overall Delay из клиента Jamulus.

Остановка отдельного аудиосервера: из его каталога выполните `docker compose stop jamulus`.

Источники: [сервер Jamulus](https://jamulus.app/wiki/Running-a-Server), [исходный релиз 3.12.5](https://github.com/jamulussoftware/jamulus/tree/r3_12_5), [протокол](https://github.com/jamulussoftware/jamulus/blob/r3_12_5/docs/JAMULUS_PROTOCOL.md).

## Установка PWA на устройства

Для удалённых устройств требуется размещение сервера за HTTPS и доступный домен. Локальный Compose по умолчанию доступен только на этом компьютере.

- iPhone/iPad: Safari → Поделиться → На экран «Домой».
- Android: меню совместимого браузера → Установить приложение.
- Windows/macOS/Linux: установка PWA из Chrome/Edge и других поддерживающих браузеров; обычная веб-версия доступна без установки.

Safari и другие браузеры отличаются поддержкой Web MIDI, Wake Lock и установки. Клавиатурные Bluetooth-педали работают через стандартные события клавиатуры; это не нативная интеграция со всеми моделями педалей. Нативных IPA/APK и публикаций в магазинах нет. Исходники пилотных desktop-клиентов Mac/Windows находятся в `desktop/`; установщики собираются отдельно.

## Разработка и проверки

```sh
npm ci --omit=optional
docker compose up -d postgres
npm run dev
npm run check
npm test
TEST_BASE=http://127.0.0.1:3180 npm test
```

Для разработки вне Docker Node.js должен быть версии 24+. При занятом порте 3180 остановите сервис приложения в Compose или используйте `PORT=3181 npm run dev`. `DATABASE_URL` по умолчанию указывает на локальный PostgreSQL из Compose на порту 54329.

Без `TEST_BASE` запускаются музыкальные тесты, интеграционный тест пропускается. С `TEST_BASE` проверяются аккаунты, сессии, изоляция, роли, приглашения, конфликтующие записи, файлы и фактическая запись в PostgreSQL. Интеграционные тесты создают свои записи и удаляют только их. Тестовой БД и API необходимо соответствовать друг другу; задайте `DATABASE_URL` при смене БД.

## Границы текущей версии

Это работающая первая версия продукта, **не подтверждённый полный функциональный паритет с Bandfix**. Подробная матрица — [docs/PARITY.md](docs/PARITY.md).

Не реализованы: вход через Apple/Google, подтверждение email и восстановление пароля, push-уведомления при закрытом приложении, платные подписки, автоматический импорт произвольных сайтов/ODT, наложение штрихов на конкретные координаты PDF/текста, MIDI-выход и произвольный MIDI Learn. На физических телефонах/педалях приложение пока не проверено. Звучание и задержка аудио требуют проверки на целевых устройствах.

JSON backup содержит тексты, сет-листы и метаданные. При импорте в другую группу файлы не копируются: их нужно загрузить отдельно. Для полноценной серверной резервной копии сохраняйте дамп PostgreSQL и volume вложений вместе.

## Размещение на сервере

Перед публичным запуском задайте собственные `POSTGRES_PASSWORD`, `DATABASE_URL`, домен HTTPS и `COOKIE_SECURE=true`. Не публикуйте порт PostgreSQL в интернет. Прокси должен сохранять исходный Host для проверки Origin и допускать загрузки до 30 МБ. SMTP/OAuth/push и операционное сопровождение требуют отдельного подключения. Гостевые пространства сейчас не удаляются по TTL; для публичного сервиса нужен управляемый жизненный цикл и лимиты хранения.

## Зависимости и источники

Проект использует `pg`, OpenSheetMusicDisplay (BSD-3-Clause) и SoundTouchJS (LGPL-2.1). Копии браузерных библиотек и их лицензии находятся в `public/vendor`. Библиотечный код не изменён. Исходные тексты учебных песен и обложки созданы для Psalmony.

Функции исследованы по [Bandfix](https://bandfix.by/), [документации сет-листов](https://bandfix.app/docs/user-guide/setlists/creating-and-editing-setlists/), [сценического режима](https://bandfix.app/docs/user-guide/live-mode/performing-on-stage/) и [редактора песен](https://bandfix.app/docs/user-guide/songs/creating-and-editing-songs/).

## Desktop и собственный звук · 0.4.0

Клиенты macOS (Intel и Apple Silicon) и Windows x64 содержат весь интерфейс Psalmony: библиотеку, сет-листы, сцену, сохранённые материалы и комнату репетиции. PWA остаётся доступной для остальных платформ. Собственный аудиодвижок написан на Rust/CPAL: CoreAudio на Mac и WASAPI на Windows, UDP, PCM16 mono 48 кГц, кадры 5 мс, AES-256-GCM и защита от повторов. Jamulus не встроен в эти клиенты; его прежний серверный пилот отключён.

Комната открывается из сет-листа кнопкой **«Открыть комнату»**. Устройства и буфер находятся в «Настройках звука». Первое подключение начинается с выключенным микрофоном и нулевой громкостью; для игры нужны проводные наушники. Микрофон, общий микс и уровни участников регулируются отдельно. Свернув комнату, можно работать с нотами; панель снизу возвращает управление звуком.

Сервер: `https://psalmony.91.226.80.181.sslip.io`, собственный UDP relay — порт 22126. Compose-конфигурация — `deploy/ekaterinburg/compose.yaml`; секреты — только в игнорируемом `.env`. PostgreSQL и вложения хранятся в разных volumes. Jamulus удалён с рабочих серверов. Аудиосервер ограничивает комнату восемью участниками, проверяет членство в PostgreSQL, не записывает звук и не смешивает комнаты разных групп. Билеты живут один час; после истечения требуется переподключение.

Клиент раздаёт встроенные ресурсы на `127.0.0.1:3188`, проксирует API через HTTPS и ограничивает локальное управление проверками Host, Origin и случайного токена процесса. Порт не публикуется в сеть. Встроенная диагностическая ручка `/desktop/network` позволяет проверить доступ к ранее скачанным материалам без связи с API; штатный режим всегда онлайн после перезапуска.

Сборка Mac: `npm run desktop:mac` (Rust targets aarch64/x86_64-apple-darwin, Xcode Command Line Tools). Windows из macOS: `PATH=/opt/homebrew/opt/llvm/bin:$PATH npm run desktop:windows` (cargo-xwin и target x86_64-pc-windows-msvc). Лицензии зависимостей собраны в `desktop/src-tauri/THIRD_PARTY_NOTICES.txt`; обновление — `node desktop/scripts/licenses.mjs`.

Установщики публикуются в `/downloads/Psalmony-0.4.0-mac-universal.dmg` и `/downloads/Psalmony-0.4.0-windows-x64.exe`. Это пилотные сборки: Mac подписан ad-hoc, без нотариализации Apple; Windows без Authenticode. Windows собран кросс-компиляцией, запуск на физическом Windows пока не проверен. PCM требует приблизительно 1 Мбит/с исходящего и до 7 Мбит/с входящего трафика на клиента при восьми участниках. Качество совместной игры, задержка и работа восьми физических устройств ещё требуют групповой проверки.

### Индикаторы соединения · 0.4.1

В комнате desktop-клиента автоматически отображаются **Ping**, **Delay (оценка)** и **Jitter сети**. Зашифрованный PING/PONG проходит через тот же UDP socket и сервер, что и аудио, раз в секунду. Микрофон можно оставить выключенным. Ответ доступен только вошедшим участникам, ограничен четырьмя ответами в секунду и не рассылается группе.

Ping — медиана последних пяти RTT. Jitter сети — сглаженная абсолютная разность соседних RTT (коэффициент 1/4); это не размер аудиобуфера и не прямое измерение межпакетного джиттера PCM. Delay — приблизительно Ping + буфер приёма + 10 мс пакетизации. Физическая задержка АЦП/ЦАП и драйверов не измеряется; сетевой путь до другого участника может отличаться. Три секунды без подтверждённого PONG сбрасывают значения в «—», переподключение начинает измерения заново.

Цвета — ориентиры интерфейса: зелёный/жёлтый/красный с границами 30/60 мс для Ping, 50/80 мс для оценки Delay и 5/15 мс для колебаний RTT. Числа и пояснения доступны независимо от цвета. Технические определения находятся в раскрываемых настройках звука.

Установщики версии 0.4.1: `/downloads/Psalmony-0.4.1-mac-universal.dmg` и `/downloads/Psalmony-0.4.1-windows-x64.exe`.

### Микшер · 0.4.2

Слева расположен индикатор входа непосредственно с аудиоустройства, до кнопки выключения отправки. Каналы справа показывают уровень декодированных пакетов с сервера: в том числе отдельный канал «Вы / С сервера». Это не копия локального индикатора. Уровень виден до фейдера; фейдер и Mute меняют только личный микс слушателя. Собственный возврат начинает с нулевой громкости и включается отдельно. Общий выход имеет отдельный индикатор, измеряемый в callback устройства после применения громкости. Индикаторы обновляются приблизительно 10 раз в секунду; значения фейдеров показаны в dB, входного индикатора — в dBFS.

Возврат своего звука включается только новым клиентом через зашифрованный JOIN `monitor-v1`. Старые клиенты продолжают получать только других участников. Сетевые показатели находятся в компактной строке под каналами. Сборки: `/downloads/Psalmony-0.4.2-mac-universal.dmg` и `/downloads/Psalmony-0.4.2-windows-x64.exe`.

### Сервер Екатеринбург · 0.4.3

Приложение, PostgreSQL, вложения, собственный аудиосервер перенесены на 91.226.80.181. HTTPS обслуживает Caddy. Обновите desktop-клиенты до 0.4.3: предыдущие сборки используют московский адрес. Актуальные установщики: `/downloads/Psalmony-0.4.3-mac-universal.dmg` и `/downloads/Psalmony-0.4.3-windows-x64.exe`.

Jamulus удалён из актуального серверного профиля и интерфейса подключения. Исторические конфигурации пилота и сохранённые результаты проверок остаются в проекте; рабочий звук использует только UDP 22126.
